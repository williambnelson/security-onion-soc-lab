# Case 004 — Metasploitable 2 Exploitation and Investigation

**Exercise Type:** Controlled Attack Exercise

1. **Scenario:** I downloaded the Metasploitable 2 virtual machine online, which is an intentionally vulnerable virtual machine meant for testing purposes. I then attempted to exploit its vulnerabilities and detect the exploitation.
2. **Environment:** The monitoring machine is a Security Onion machine accessed through an Ubuntu Linux machine. It monitors a Kali Linux machine that acts as the attacker, and an Ubuntu Linux machine downloaded from Metasploitable 2 which acts as the victim.
3. **Attack Method:** I researched what tactics could be used to exploit the Metasploitable 2 system. The first thing I did was use nmap to scan for open ports on the victim system. Since ports 512-514 (r services) were open, I could use rlogin to gain root access to the target system. Since port 2049 (NFS) was also open, I used rpcinfo and showmount to find the root file system was exported by the server. I then generated an RSA key pair and used a mounted drive to plant one of the shared keys in the victim’s file system. This allowed me to start an SSH session as a root user on the target system.
4. **Vulnerabilities:** There were a number of intentional vulnerabilities within the target system, including the high number of open vulnerable services. The two I chose to exploit were the open r services and the exported NFS root file system.
5. **Timeline:** I first made contact with the target system on 2026-09-15 16:10:37.699 and finished my exploitation around 2026-09-15 16:28:52.884.
6. **ATT&CK Mapping:** Since I used networking tools to scan the system, my reconnaissance would classify as T1595 – Active Scanning. My use of the showmount -e command would fall under T1135 – Network Share Discovery.
7. **Detection:** The Security Onion system detected a lot of my exploitation. For one, it detected my use of nmap via the “ET SCAN Possible Nmap User-Agent Observed” alert. It also detected my use of rlogin via the “GPL MISC rlogin root” alert. Furthermore, it detected my drive-mounting via the “GPL RPC portmap mountd request UDP” alert. Finally, it detected my usage of SSH and generated the “ET SCAN Potential SSH Scan OUTBOUND” alert. All of these alerts have the proper IP address and port information. There were more alerts, but these were the main ones that caught my eye.
8. **Remediation:** The first thing I attempted to do was close ports 512-514 on the Metasploitable system via the “sudo kill” command. This appeared to close the ports, so the next thing I tried to do was close port 2049 in the same manner. This did not work, so instead I researched the problem and found the “sudo exportfs -u” command does not close the port, but does stop the file system from being shared. I used that command for the root directory.
9. **Change in Exploitability:** Upon returning to the attacker system and re-attempting my previous exploits, I immediately noticed a change. For one, ports 512-514 no longer appeared on the nmap scan, indicating I could no longer access them. Surely enough, my rlogin attempt failed with the message “Could not make a connection.” Next, I attempted to mount a virtual drive with an SSH key, and that attempt failed with the message “failed to apply fstab options”; After doing some research, it seems to indicate I no longer have the permissions needed to carry out the attack from the attacking system.
10. **Lessons Learned:** I learned a lot about penetration testing: How to scan a system, some of the services that are exploitable, and some methods to exploit those services. I also learned about system defense, including how to close a port and how to shut down certain services. Finally, this exercise gave me firsthand experience on the importance of system hardening and closing unneeded services.
