# Case 005 — OWASP Juice Shop Challenges and Detection

**Exercise Type:** Controlled Attack Exercise

1. **Scenario:** I downloaded and ran OWASP Juice Shop, which is an intentionally vulnerable web application meant for penetration testing. I attempted two challenges from separate categories and assessed how my monitoring system was able to detect each one.
2. **Environment:** The monitoring machine is a Security Onion machine accessed through an Ubuntu Linux machine. It monitors a Kali Linux machine that acts as the attacker, and an Ubuntu Server machine running OWASP Juice Shop which acts as the victim.
3. **Challenge 1:** The first challenge I attempted was “Access a Confidential Document”. This challenge involved going to a publicly accessible page and deleting part of the URL to perform directory traversal. From there, I could view a number of sensitive documents, although some were still inaccessible due to the site’s security measures; Those documents generated 403 errors upon clicking them.
4. **Detection:** Security Onion generated alerts when I attempted to access the documents that generated 403 errors. However, when I successfully viewed other confidential documents, Security Onion only generated zeek alerts under Hunt. Those required a bit more digging to find, and additional investigation to determine their nature and severity.
5. **Challenge 2:** The second challenge I attempted was “Leave a Zero-Star Rating”. This challenge involved going to the customer feedback page and going through the normal steps to leave a review, minus leaving a rating. From there, I inspected the “Submit” button and deleted the field which disabled it. This allowed me to submit my review with no rating, which defaulted to zero stars since the website should normally not allow that.
6. **Detection:** Security Onion did not detect my exploits for the second challenge. It generated a few alerts under Hunt, but none of them indicated what happened or the presence of a potential threat.
7. **Lessons Learned:** There are two main things to take away from these exercises. First of all, it is important for a security professional to fully examine suspicious activity. The zeek notifications generated by the first challenge might seem benign, but upon further investigation indicate a compromise of sensitive information. Second, a well-designed NIDS cannot replace secure application design. There are certain types of exploits and attacks an NIDS will ignore, but which may have unintended or harmful consequences for an application. It is therefore important to ensure an unauthorized user cannot carry out those exploits, both to increase security and to reduce the number of alerts a cybersecurity professional needs to investigate.
