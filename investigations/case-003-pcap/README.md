# Case 003 — Security Onion PCAP Alert Investigation

**Exercise Type:** Known Synthetic/Validation Exercise

1. **Scenario:** I downloaded a training PCAP online and uploaded it to Security Onion, then analyzed the generated alerts. The PCAP is mean to represent an attack against the network, though I did not check to see the exact kind of attack, as I wanted to discover that for myself.
2. **Environment:** The environment is a Security Onion machine accessed through an Ubuntu Linux machine.
3. **Investigation Method:** The first thing I did was look at the generated network alerts. I filtered by category to try to find patterns in specific activity, taking note of specific IP addresses associated with different types of alerts. 
4. **Evidence:** I noticed a number of zeek.ldap alerts, which led me to believe the simulated attack was likely to steal user credentials. I also noticed some zeek.kerberos alerts, which I thought could indicate an attempt at a Kerberoasting attack. I noticed some issues listed with certificates, which I thought could indicate a faulty machine used as an entry point to access the network.
5. **Timeline:** Alerts like the indicated one started at 2:07:32 and ended at 2:21:32.
6. **ATT&CK Mapping:** I have determined the ATT&CK mappings based on a combination of my own analysis and AI assistance. Since many alerts generated from port 80 (HTTP), the attack falls under T1071.001 - Application Layer Protocol: Web Protocols. As I elaborate on later, the AI determined the attack was carried out via HTTP POST requests from a C2 channel. This would classify the attack under T1041 - Exfiltration Over C2 Channel, as well as T1132.001 - Data Encoding: Standard Encoding.
7. **Manual Findings:** Upon further investigation, there were many plaintext or HTML files transferred during the network activity; Given the high volume of LDAP alerts, my theory about stealing user credentials was likely correct. However, hunting the Kerberos activity yielded no alerts, indicating it may have simply been normal network activity flagged by the system. Digging into the certificate problems, it appeared the issues were not with a specific machine, but rather with the network itself. 
8. **AI-Assisted Findings:** The AI noticed a variety of outward HTTP communications from a certain IP address. Based on the combination of unusual protocol and the unusual destination addresses compared to the rest of the network, it determined the machine in question had been compromised and acted as a command-and-control machine. In addition, it stated the HTTP packet captures contained POST requests, and used obfuscation to hide sensitive information being exfiltrated.
9. **Where AI Was Wrong:** As far as I can tell, the AI made no errors in its judgement. When I looked into the aforementioned packet captures, much of it was indeed obfuscated despite the apparently high volume of plaintext files being transferred. In the process, I also noticed file paths related to PKI, potentially indicating modified certificates. There was also seemingly "security" and "requested privileges" being modified.
10. **Final Analyst Judgment:** My initial hypothesis of the PCAP representing an attack to steal user credentials was correct. However, I have no definitive proof the detected Kerberos activity was part of the exfiltration. Since Kerberoasting involves cracking hashes offline, there may have been activity the system simply did not detect, but I cannot say for certain either way. In addition, my theories of issues with an individual machine or the network itself having security issues cannot be definitively proven; There was a compromised machine on the network which was used to leverage an attack that seemingly modified network settings, but I cannot say whether the network itself was faulty beforehand.
11. **Lessons Learned:** Since I relied on AI for ATT&CK mappings during this exercise, I have learned it is important to keep said mappings in mind when initially determining the exact nature of an attack. They are not perfect, but they provide data which I may compare to the data Security Onion gives me to draw a more informed conclusion.
